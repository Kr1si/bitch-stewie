# How bitch-stewie uses the LongCat 2.0 API

LongCat-2.0 is an **Anthropic-Messages-native** LLM endpoint
(`https://api.longcat.chat/anthropic`). Because it speaks the Anthropic
Messages API, two very different consumers in this repo can both talk to it
with nothing more than a base-url + auth swap:

1. **LangChain agents** (orchestrator, planner, goal-creator) — via
   `langchain_anthropic.ChatAnthropic`.
2. **Claude Code instances** (delegated coding, deep research) — via the
   `claude_agent_sdk`, which reads standard `ANTHROPIC_*` env vars.

Both are pointed at LongCat in production via `docker-compose.prod.yml` +
`docker/.env.example`. The single source of truth for the endpoint + token is
the set of `ANTHROPIC_*` / `ASSISTANT_CC_*` env vars; the code never hardcodes
the LongCat key.

---

## 1. LangChain agents (ChatAnthropic)

### The auth gotcha that shapes everything

`ChatAnthropic` authenticates with the `x-api-key` header by default. **LongCat
rejects `x-api-key` with a 401** — it requires `Authorization: Bearer <key>`.
So every LangChain agent in this repo builds its model through ONE helper that
passes the Bearer token explicitly:

`backend/src/assistant/application/orchestrator/factory.py` → `_build_chat_model()`

```python
token = os.environ.get("ANTHROPIC_AUTH_TOKEN") or os.environ.get("ANTHROPIC_API_KEY", "")
default_base = "https://api.longcat.chat/anthropic"
base_url = os.environ.get("ANTHROPIC_BASE_URL", default_base)
name = settings.default_model.split(":", 1)[-1] if settings.default_model else "LongCat-2.0"
return ChatAnthropic(
    model=name,
    anthropic_api_url=base_url,
    default_headers={"Authorization": f"Bearer {token}", "Content-Type": "application/json"},
)
```

Key points:
- `default_model` is the provider-prefixed string `anthropic:LongCat-2.0`
  (`backend/src/assistant/shared/config.py`). The `anthropic:` prefix is how
  `init_chat_model()`/`deepagents` resolve the provider; `_build_chat_model`
  strips it to get the bare model name `LongCat-2.0`.
- The Bearer token comes from `ANTHROPIC_AUTH_TOKEN` (fallback
  `ANTHROPIC_API_KEY`). It is passed via `default_headers`, NOT set as the
  `api_key`, precisely so `ChatAnthropic` sends `Authorization: Bearer` instead
  of `x-api-key`.
- Base URL defaults to `https://api.longcat.chat/anthropic`, overridable with
  `ANTHROPIC_BASE_URL`.

### Who calls `_build_chat_model` (and why they all must)

| Consumer | File | How it builds the model |
|---|---|---|
| **Orchestrator** (deep agent + 4 subagents) | `factory.py` → `build_orchestrator()` | Directly calls `_build_chat_model(settings)` |
| **Planner** (iterative plan builder) | `planner.py` → `build_planner()` | Imports `_build_chat_model` from factory |
| **Goal-creator** (interview → Goal JSON graph) | `goal_creator_graph.py` → `_model()` | Imports `_build_chat_model` from factory |

The planner and goal-creator **must not** use a bare `init_chat_model("anthropic:...")`
string — that creates a default `ChatAnthropic` that sends `x-api-key`, which
LongCat rejects. This was a verified bug (see `VERIFICATION_REPORT.md` §2:
"Planner + goal-creator — LongCat auth failure"). The fix was routing both
through the auth-aware builder. **Rule: any new LangChain agent reuses
`_build_chat_model`, never a raw model string.**

### The `ANTHROPIC_API_URL` mirror

`ChatAnthropic` reads `ANTHROPIC_API_URL` (not `ANTHROPIC_BASE_URL`) for its
base URL. `config.py:apply_anthropic_env()` mirrors the platform's
`ANTHROPIC_BASE_URL` across to `ANTHROPIC_API_URL` — but deliberately does
**not** mirror `ANTHROPIC_AUTH_TOKEN` → `ANTHROPIC_API_KEY`, because that would
make `ChatAnthropic` send `x-api-key` and LongCat would 401. Auth is handled
entirely by the explicit Bearer header in `_build_chat_model`.

### Config defaults (`backend/src/assistant/shared/config.py`)

```python
default_model: str = "anthropic:LongCat-2.0"   # orchestrator/planner LLM
# (CC settings — see section 2)
cc_anthropic_base_url: str = "http://localhost:11434"  # CODE default = local Ollama
cc_anthropic_auth_token: str = "ollama"
cc_model: str = "glm-5.2:cloud"
```

Note the split: the orchestrator's `default_model` defaults to LongCat in
code, while the CC provider defaults to **local Ollama** in code and is
**overridden to LongCat by compose in production**.

## 2. Claude Code instances (claude_agent_sdk)

Delegated coding sessions and deep-research runs use the Claude Code Agent SDK,
which talks Anthropic Messages natively. The SDK picks up its endpoint and auth
from standard env vars — so pointing it at LongCat is purely an environment
configuration, with no special auth code.

### How the env vars reach the SDK

`backend/src/assistant/infrastructure/cc_bridge/runner.py` →
`DelegationRunner._options()` builds `ClaudeAgentOptions` and sets:

```python
env = {
    "ANTHROPIC_BASE_URL": self._settings.cc_anthropic_base_url,
    "ANTHROPIC_AUTH_TOKEN": self._settings.cc_anthropic_auth_token,
    "API_TIMEOUT_MS": self._settings.cc_api_timeout_ms,
    "CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC": "1",
}
return ClaudeAgentOptions(
    model=self._settings.cc_model,
    ...
    env=env,
)
```

The SDK reads `ANTHROPIC_BASE_URL` + `ANTHROPIC_AUTH_TOKEN` from the
process environment (the `env` block above places them there) and sends
`Authorization: Bearer <token>` automatically — no header hack needed,
because the SDK uses Bearer auth by default.

### Config + compose wiring

Code defaults (local Ollama, for dev) → overridden in production:

| Var | Code default (`config.py`) | Production (`docker-compose.prod.yml`) |
|---|---|---|
| `cc_anthropic_base_url` | `http://localhost:11434` | `https://api.longcat.chat/anthropic` |
| `cc_anthropic_auth_token` | `ollama` | `ASSISTANT_CC_ANTHROPIC_AUTH_TOKEN` (your LongCat key) |
| `cc_model` | `glm-5.2:cloud` | `LongCat-2.0` |
| `cc_api_timeout_ms` | `3000000` | `3000000` |

`docker-compose.prod.yml` sets these on **both** `backend` and `worker`
services, all sourced from `docker/.env.example`:

```yaml
ASSISTANT_CC_ANTHROPIC_BASE_URL: ${ASSISTANT_CC_ANTHROPIC_BASE_URL:-https://api.longcat.chat/anthropic}
ASSISTANT_CC_ANTHROPIC_AUTH_TOKEN: ${ASSISTANT_CC_ANTHROPIC_AUTH_TOKEN:-}
ASSISTANT_CC_MODEL: ${ASSISTANT_CC_MODEL:-LongCat-2.0}
# orchestrator/planner LLM mirrors the CC endpoint by default:
ANTHROPIC_BASE_URL: ${ASSISTANT_CC_ANTHROPIC_BASE_URL:-https://api.longcat.chat/anthropic}
ANTHROPIC_API_KEY: ${ASSISTANT_CC_ANTHROPIC_AUTH_TOKEN:-}
ANTHROPIC_AUTH_TOKEN: ${ASSISTANT_CC_ANTHROPIC_AUTH_TOKEN:-}
```

So in production the **same LongCat key** (`ASSISTANT_CC_ANTHROPIC_AUTH_TOKEN`)
backs both the LangChain agents (`ANTHROPIC_AUTH_TOKEN` → Bearer header) and
the CC instances (`ANTHROPIC_AUTH_TOKEN` → SDK Bearer auth).

### What runs on LongCat via the CC SDK

- **Delegated coding** (`delegate_coding_task` → `CCWorker.delegate()` →
  `DelegationRunner.run()`): a full implement → test → `/code-review` loop on a
  branch, milestone-gated.
- **Deep research** (`deep_research` tool → `run_deep_research()` →
  `CCWorker.run_prompt()`): a headless one-shot CC session running the staged
  `deep-research-review` skill; the report is ingested into the Qdrant KB.
- **Deep-research API** (`POST /api/research/deep/stream`): the same
  `run_prompt` path dispatched via `asyncio.to_thread` so the minutes-long
  blocking call doesn't stall the event loop.

All of these run on the **cc-worker** thread (own event loop), because the SDK
needs asyncio subprocess support and blocks the calling thread.

## Summary: one provider, two auth paths

| | LangChain agents | Claude Code SDK |
|---|---|---|
| **Consumer** | `ChatAnthropic` (via `deepagents`) | `claude_agent_sdk` |
| **Base URL** | `ANTHROPIC_BASE_URL` (→ `ANTHROPIC_API_URL` mirror) | `ANTHROPIC_BASE_URL` |
| **Auth mechanism** | Explicit `Authorization: Bearer` via `default_headers` (the `x-api-key` default would 401) | SDK Bearer auth by default (reads `ANTHROPIC_AUTH_TOKEN`) |
| **Model string** | `anthropic:LongCat-2.0` (prefix stripped to `LongCat-2.0`) | `LongCat-2.0` |
| **Wired in** | `factory.py:_build_chat_model` (shared by orchestrator/planner/goal-creator) | `docker-compose.prod.yml` env → `runner.py` → `ClaudeAgentOptions` |

The only thing that makes LongCat work for LangChain is the explicit Bearer
header in `_build_chat_model` — everything else (base URL, model name, token
source) is ordinary configuration. For the CC SDK it's purely env vars, no
code change.
